## M1: Location — behaviour taxonomy annotation, layer sweep, linear probe per behaviour  → C1 primary

**method_sensitive**: `[n_pairs, sites, metric, gpu_hours]` — the concrete extractor (mean-of-differences vs. logistic-probe vs. LDA-direction) is picked by `/mechanism-skills` at the experiment stage; the fields above may be re-bound at routing time without a plan rewrite.

**Priority**: MUST-RUN.

**Cmd (template)**:
```
python run_M1_locate.py \
  --model_path $MODEL_DIR/DeepSeek-R1-Distill-Llama-8B \
  --contrast_corpus data/contrast/auxiliary_corpus.jsonl \
  --behaviour_taxonomy configs/behaviour_taxonomy.yaml \
  --layer_range 0:end:1 \
  --extractor mean_of_differences \
  --n_pairs_reference 200 \
  --out_dir runs/M1/
```

**Steps**:
1. **Behaviour taxonomy prompt v1** — freeze at `configs/behaviour_taxonomy.yaml` (four behaviours + one-sentence definition + 3 few-shot examples each). Never edit past M1.
2. **Auxiliary corpus annotation** — LLM-judge tags every chain excerpt with `{behaviour: present | absent}` labels using the frozen prompt. Sanity check: re-annotate 10% and record inter-run agreement (Cohen κ; target ≥ 0.6).
3. **Split** — 80% extract / 20% held-out per behaviour.
4. **Activation capture** — for every extract-split excerpt, cache the residual-stream activation at the last-token position of the excerpt for every layer L ∈ {0, …, end}.
5. **Per-behaviour, per-layer extraction** — compute the mean-difference direction v_b(L) and train a linear probe on the extract split.
6. **Layer selection L\*(b)** — choose the layer that maximises held-out ROC-AUC per behaviour. Also compute first-PC alignment: `|cos(v_b(L*), first_PC(diff_activations))|`.

**Predicates**:
- Per behaviour b, at chosen L*(b): held-out ROC-AUC ≥ 0.75 AND first-PC alignment |cos| ≥ 0.7 (pre-registered floors, illustrative; final numbers stated in the run's `results.json`).
- At L*(b), no other layer trivially matches the same predicates while being an obvious pathology (e.g., layer 0 or embedding-layer scores) — brief sanity note in `results.json`.

**Verifies**: C1 primarily; feeds M2, M3, M4.

**Expected output**: `runs/M1/results.json` including `per_behaviour: {behaviour: {L_star, roc_auc_test, first_pc_align, v_b_path}}` + `annotation_kappa`; direction files `runs/M1/directions/v_<behaviour>_L<L_star>.pt`.

**Estimated GPU-hours**: ~1.5 h on 1 × A100 40G (single forward-pass activation cache over the ~200-chain auxiliary corpus + probe fit is CPU-friendly). *Provisional — `method_sensitive: [gpu_hours]`.*

## M2: Location — small-pool contrastive extraction sweep (C2)  → C2

**method_sensitive**: `[n_pairs, sites, metric, gpu_hours]`.

**Depends on**: M1 (needs the frozen behaviour taxonomy + auxiliary corpus + reference L*(b) from M1).

**Grid**:
```
n_pairs: [10, 25, 50, 100, 200]
behaviour: [expressing_uncertainty, generating_validation_examples, backtracking, self-correction]
seed: [0, 1, 2]
```
(→ 5 × 4 × 3 = 60 lightweight extraction runs; each run is a re-shuffle of the extract pool, mean-difference recompute, and cached-activation re-use from M1.)

**Priority**: MUST-RUN.

**Cmd (template)**:
```
python run_M2_smallpool.py \
  --activations_cache runs/M1/activations/ \
  --behaviour ${behaviour} \
  --L $(python -c "import json;print(json.load(open('runs/M1/results.json'))['per_behaviour']['${behaviour}']['L_star'])") \
  --n_pairs ${n_pairs} \
  --seed ${seed} \
  --out runs/M2/n${n_pairs}_${behaviour}_s${seed}.json
```

**Steps**:
1. For each `(behaviour, n_pairs, seed)` combination — sample `n_pairs` positive + `n_pairs` negative excerpts from the extract split, compute the mean-difference direction v_b(n_pairs, seed).
2. **Split-half stability** — split the same sample into halves and compute cosine between the two half-directions.
3. **Steering-effect preservation** — apply v_b(n_pairs, seed) at a fixed α (the M3 operating α, or a mid-grid α if M3 is not yet run) to a fixed 50-task subset of the 500-benchmark; measure behaviour-rate change. Ratio-to-large-pool = rate_change(n_pairs) / rate_change(n_pairs=200).

**Predicates**:
- Split-half cosine |cos| ≥ 0.7 at every n_pairs ≥ 25 (illustrative floor).
- Steering-effect ratio-to-large-pool ≥ 0.8 at n_pairs ≤ 200 for every behaviour.

**Verifies**: C2 primarily; sanity-check on C1's direction quality.

**Expected output**: `runs/M2/results_summary.json` — n_pairs × behaviour × seed table; a plot `n_pairs_vs_stability.png`.

**Estimated GPU-hours**: ~1.0 h on 1 × A100 40G (activations cached from M1 → only inference for the 50-task subset per `(behaviour, n_pairs, seed)`; batched to ~1 min per run × 60 runs). *Provisional — `method_sensitive: [gpu_hours]`.*

## M3: Causal Intervention — α-sweep dose-response + off-target specificity (C3)  → C3

**method_sensitive**: `[n_pairs, sites, metric, gpu_hours]` — concrete intervention hook (residual-stream add-hook layer position vs. attention-output vs. MLP-output) is routed at experiment stage.

**Depends on**: M1 (v_b at L*(b)).

**Grid**:
```
behaviour: [expressing_uncertainty, generating_validation_examples, backtracking, self-correction]
alpha: [-3.0, -2.0, -1.0, -0.5, 0.0, 0.5, 1.0, 2.0, 3.0]   # in units of σ = std of residual stream activations at L*(b)
seed: [0]   # per α — extended in verify stage
```
(→ 4 × 9 × 1 = 36 generation runs; each = greedy or fixed-seed decode of the 500-task benchmark under steering hook at L*(b) with coefficient α·σ.)

**Priority**: MUST-RUN.

**Cmd (template)**:
```
python run_M3_steer.py \
  --model_path $MODEL_DIR/DeepSeek-R1-Distill-Llama-8B \
  --direction runs/M1/directions/v_${behaviour}_L*.pt \
  --alpha ${alpha} \
  --benchmark data/benchmark_500.jsonl \
  --seed ${seed} \
  --out runs/M3/${behaviour}_a${alpha}_s${seed}.json
```

**Steps**:
1. For each `(behaviour, α)` — add α·σ_L*·v_b at layer L*(b) at every post-prompt token position; generate the full chain + final answer on all 500 tasks.
2. **Behaviour-rate scoring** — LLM-judge annotates each generated chain with the same behaviour taxonomy prompt (frozen from M1) and reports per-behaviour rate.
3. **Sign check** — for each behaviour b: sign(rate_b(+α_op) − rate_b(0)) = +; sign(rate_b(−α_op) − rate_b(0)) = −. Operating α_op = smallest |α| that clears both signs.
4. **Monotonicity** — Spearman ρ(α, rate_b) on the α-grid.
5. **Off-target specificity** — for the same α, rate the same chain on all four behaviours; specificity_b = 1 − mean_{b′≠b}|Δrate_b′| / |Δrate_b|.
6. **Coherence sanity** — LLM-judge flags each chain as "coherent" or "gibberish"; any α with > 10% gibberish is excluded from monotonicity fit.

**Predicates**:
- Sign check passes for all four behaviours at some α_op ∈ [0.5σ, 3σ].
- Spearman ρ(α, rate_b) ≥ 0.7 on the non-gibberish α-range.
- Off-target |Δrate| ≤ 50% of on-target |Δrate| for each behaviour.

**Verifies**: C3.

**Expected output**: `runs/M3/results_summary.json` — behaviour × α × per-task rate table; three plots (`dose_response.png`, `specificity_matrix.png`, `coherence_vs_alpha.png`).

**Estimated GPU-hours**: ~2.0 h on 1 × A100 40G (500 tasks × 9 α × 4 behaviours = 18k generations; batching + max-new-tokens ≤ 1024 keeps this ≈ 2 h; caching the unsteered α=0 baseline once across behaviours). *Provisional — `method_sensitive: [gpu_hours]`.*

## M4: Tuning & Editing — steering vs. prompt engineering + Thinking Intervention Pareto (C4)  → C4

**method_sensitive**: `[n_pairs, sites, metric, gpu_hours]`.

**Depends on**: M3 (needs the α operating range + baseline accuracy at α=0).

**Grid**:
```
behaviour: [expressing_uncertainty, generating_validation_examples, backtracking, self-correction]
controller: [
  steering_alpha_neg2,      # steering at α = −2σ (suppress)
  steering_alpha_neg1,      # steering at α = −1σ (mild suppress)
  steering_alpha_pos1,      # steering at α = +1σ (mild amplify)
  steering_alpha_pos2,      # steering at α = +2σ (amplify)
  prompt_suppress,          # NL instruction "Do less of B"
  prompt_amplify,           # NL instruction "Do more of B"
  thinking_intervention_suppress,   # token-insertion baseline (2503.24370-style)
  thinking_intervention_amplify,
]
seed: [0]
```
(→ 4 × 8 × 1 = 32 generation runs.)

**Priority**: MUST-RUN.

**Cmd (template)**:
```
python run_M4_control_compare.py \
  --model_path $MODEL_DIR/DeepSeek-R1-Distill-Llama-8B \
  --behaviour ${behaviour} \
  --controller ${controller} \
  --directions_dir runs/M1/directions/ \
  --benchmark data/benchmark_500.jsonl \
  --seed ${seed} \
  --out runs/M4/${behaviour}_${controller}_s${seed}.json
```

**Steps**:
1. Generate the 500-task chain under every controller.
2. LLM-judge scores (i) behaviour-rate per chain, (ii) final-answer accuracy.
3. **Granularity metric** — for each (controller family) plot behaviour-rate vs. accuracy; count `n_distinct_operating_points` = number of controller instances whose (rate, accuracy) point is separated from every other same-family point by ≥ ε_r on rate and ≥ ε_a on accuracy (pre-registered ε_r = 5 pts, ε_a = 1 pt).
4. **Matched-rate accuracy comparison** — for each behaviour b, find pairs of (steering, prompt) instances whose rate differs by ≤ 2 pts; compare their accuracy delta.
5. **Preservation at operating α** — accuracy(steering_α_op) ≥ accuracy(α=0) − 3 pts.

**Predicates**:
- `n_distinct_operating_points(steering) > n_distinct_operating_points(prompt)` and `> n_distinct_operating_points(thinking_intervention)` on each behaviour.
- Matched-rate accuracy(steering) ≥ accuracy(prompt) − 2 pts for every rate-matched pair.
- accuracy(steering @ α_op) ≥ accuracy(α=0) − 3 pts for every behaviour.

**Verifies**: C4.

**Expected output**: `runs/M4/results_summary.json` — controller × behaviour × (rate, accuracy) table; a Pareto plot per behaviour `pareto_<behaviour>.png`.

**Estimated GPU-hours**: ~1.0 h on 1 × A100 40G (32 configurations × 500 tasks ≈ 16k generations; α=0 already cached from M3). *Provisional — `method_sensitive: [gpu_hours]`.*

1. **M1** (Location — layer sweep + probe) — no dependency.

## Decision Gates

- After **M1**: if C1 predicate fails on any behaviour, log the behaviour as "linear-direction unverified"; still proceed to M2/M3 on the passing behaviours; C1 verdict = partial.
- After **M2**: if C2 predicate fails at n_pairs ≤ 200 for a behaviour, run one extra size (n_pairs = 500) as a last-mile check within the budget.
- After **M3**: if C3 predicate fails on sign or monotonicity for a behaviour, re-run that behaviour with a finer α-grid around the failing region within the M3 budget; if specificity fails, log and carry on (specificity failure is a limitation, not a fatal).
- After **M4**: if C4 preservation fails, run one narrower-α operating point (α_op / 2) as a final probe.
