## Check A — Ground-Truth Provenance

**Status: PASS**

Ground truth for C2 is the HackerRank sample test cases (`sample_tests` in `eval_set.jsonl`). Test case inputs and expected outputs are loaded from the dataset file, not generated by the model. The comparison uses `normalise_output(out) == expected` — exact string match against the provided test cases. This is genuine external GT.

**Concern raised in task.md**: "Compile+run sandbox for HackerRank test-case pass rate — check it isn't accepting empty outputs or timing out silently."

Inspection of `c2_hackerrank.py`'s `score_output` function:
- Empty code: `if not code.strip(): return {..., "num_passed": 0, "pass_rate": 0.0, "note": "no_valid_code"}` — empty outputs correctly score 0.
- Timeout: `subprocess.TimeoutExpired` raises `TIMEOUT` in stderr and returns `code_r=124` — the loop checks `if code_r != 0: runtime_err += 1; continue` (no pass credit). Silent timeouts cannot occur.
- Compile error: `if c.returncode != 0: return ("", f"COMPILE_ERR:...", c.returncode)` — also scores 0.

**Verdict**: Empty output protection is correct; timeout protection is correct. No silent acceptance of empty/timed-out outputs.

## Check B — Score Normalization

**Status: PASS**

Pass rate = `num_passed / max(1, len(tests))` per problem, averaged across problems. No normalization by model's own output. The 3 conditions (default/cpp_prompt/cpp_steered) are evaluated independently on the same held-out problems with the same test cases.

## Check C — Result File Existence (claim-scoped)

**Status: WARN**

- `runs/C2_hackerrank/summary.json` — exists and is well-populated with dev_results, held_out aggregates, alpha_star, n_held=10.
- `runs/C2_hackerrank/held_details.jsonl` — referenced in claims_ledger.json as an artifact; script writes it.
- `runs/C2_hackerrank/dev_details.jsonl` — written by script.

**WARN — Under-power**: The summary.json shows `n_held=10` (10 held-out problems, not the plan's 30). This is the `suspected_under_power` flag. The mean_pass_rate standard deviations are very high (std≈0.49) on a binary problem-pass outcome for n=10, meaning the reported differences (0.600 vs 0.567) are statistically meaningless at this sample size. The negative verdict ("not-supported") is provisional.

**WARN — Language detection reliability**: `cpp_frac` and `py_frac` are derived from `extract_code_block` heuristics (regex for `#include`, `int main(`, `std::`, `def`, `import`, `print(`). For the cpp_steered condition, `cpp_frac=0.00, py_frac=1.00` — all steered outputs were classified as Python. This is consistent with the finding that the RFM vector didn't switch output language, but the 0.00/1.00 binary is believable given the regex-based detection (Python outputs clearly have Python syntax).

## Check D — Dead Code

**Status: PASS**

`score_output` is called on every (problem, generation) pair. `make_prompt`, `run_python`, `run_cpp`, `extract_code_block` are all in the active execution path. No evidence of dead metric code.

## Check E — Scope (claim-scoped)

**Status: WARN**

The claim states the C++ vector "raises test-case pass rate on HackerRank algorithmic problems above both the default (Python) output and prompt-only 'Answer in C++.'". The actual result is 10 held-out problems × 2 seeds vs the plan's 30 held-out. The reported effect is small and within noise. The scope language is technically accurate (HackerRank subset) but the power is insufficient to confirm or deny the claim.

Additionally, the dev alpha-sweep was also on 10 problems (alpha_star=3.0 chosen on dev), and the held-out evaluation uses a different 10 problems. This separation is correct per the design but limits statistical power severely.

## Check F — Evaluation Type

**Status: PASS**

Evaluation type: `real_gt` — HackerRank test cases with exact string matching. The most rigorous possible evaluation for code correctness. No synthetic proxy involved.

## Overall Verdict

**overall_verdict: WARN**

Main findings:
- GT provenance, normalization, dead code, eval type: all PASS
- Result files: exist but n_held=10 (suspected under-power flagged explicitly in EXPERIMENT_RESULTS.md)
- Scope: under-powered; negative verdict is provisional
- Language detection: heuristic but consistent with the null language-switch finding

The experimental methodology is sound, but the sample size (10 held-out problems) is insufficient to draw statistical conclusions. The negative verdict is defensible as provisional, not as a confirmed falsification.
