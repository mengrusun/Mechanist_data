# Final Proposal — Verbalized Confidence Is Cached Mid-Generation, Not Computed on Demand

**Behavior source**: `given` (task.md).
**Mechanism**: `discovery` — routed to Location → Causal Intervention.
**Date**: 2026-07-13.

---

## 1. Problem Anchor (do not move)

For a decoder-only LLM asked to (i) answer a factual question and then (ii) verbalize a confidence value about that answer, **where and when is the verbalized confidence value decided inside the model?** Two competing hypotheses:

- **H_cache** (the task.md claim): The confidence value is written into the residual-stream hidden states at **post-answer positions** (the small window of tokens immediately following the answer, before the confidence token) and is **retrieved** from that cache when the confidence token is generated.
- **H_on-demand** (the null): The confidence value is freshly computed at the **confidence-generation position** from the answer token's log-probability (or a fresh reading of the answer), with no meaningful cache at post-answer positions.

The task pins the claim as H_cache and the plan below verifies it end-to-end.

---

## 2. Method Thesis (one sentence)

Combine a per-position × per-layer **linear-probe screen** at post-answer positions (Location) with three **causal interventions** — residual-stream **patching** for sufficiency, **attention-block / path-patching** for the retrieval-path bottleneck, and **direction steering** for a signed dose-response — plus a matched **specificity + null-controls** battery, to test whether the eventual verbalized confidence is *read from* a hidden-state cache at answer-adjacent positions rather than *recomputed* at the confidence-generation position.

---

## 3. Testing Approach

We treat the claim as one causal-mediation claim with two connected sub-parts and test them with a single, unified suite on gemma-3-27b-pt (62 layers) evaluated on TriviaQA.

### 3.1 Setup: the prompt template

Every trial uses a single fixed template of the form:

```
Q: <question>
A: <answer generated by the model><EOA>
Confidence (0-100): <conf>
```

`<EOA>` is either an explicit end-of-answer marker (e.g., a newline) or a small, fixed set of end-of-answer tokens. The **post-answer window** is the token positions of `<EOA>` plus a small number of following template tokens up to and including the position just before `<conf>`. The **confidence-generation position** is the position at which `<conf>` is decoded. We hold the template fixed across all controlled comparisons and use paraphrase variants only for the confound checks (§3.5).

### 3.2 Data preparation (M1)

Run gemma-3-27b-pt on TriviaQA (validation split; exact `used_n` bound in M1 — floor: ≥500 items per split for the probe train / eval / patch pool, target ≥1500 with the budget). For every item, record:

- question, answer, correctness (against TriviaQA gold),
- verbalized confidence value (parsed from `<conf>` — integer 0..100),
- answer-token log-probability(s),
- residual-stream activations at every layer in the **62-layer probe grid** (see §3.6) for (a) every position in the post-answer window and (b) the confidence-generation position.

Report variance across ≥3 seeds and at least one paraphrase of the template (only for the confound check — the probe / patching runs use the fixed template).

### 3.3 Location — correlational screen (M2)

Train a **ridge linear probe** at each `(position ∈ post-answer window, layer ∈ 62-layer grid)` on residual-stream activations to predict the model's verbalized confidence value (regression) on a held-out split. Report a per-position × per-layer probe R² (or Spearman ρ) heatmap. Baselines: (a) log-prob-only, (b) probe on activations at the confidence-generation position (should be at most on-par if the value is *already* determined post-answer), (c) shuffled labels (chance).

**Location output**: the top-K `(position, layer)` cache candidates, ranked by cache-vs-baseline R² gap.

### 3.4 Causal Intervention — three complementary tests

**M3 — Residual-stream patching (sufficiency).** Build clean/corrupted paired runs where the corruption changes the *item*'s expected confidence (e.g., pair a well-known TriviaQA item — high correctness / high verbal confidence — with a rare item — low correctness / low verbal confidence — matched for surface length). Patch the residual stream from corrupted → clean at each top `(position, layer)` candidate from M2. Effect metric: shift in the verbalized confidence distribution (KL, or Δ mean confidence) vs. answer-token distribution (Δ answer log-prob). **Sufficiency claim**: patching at the cache candidate moves confidence toward the corrupted run's confidence, while answer prediction is comparatively preserved.

**M4 — Retrieval-path attention-block.** Zero the attention weights *from* the confidence-generation position *to* the identified cache position(s), across (i) the layer(s) that carried the M2 probe signal and (ii) later layers where the retrieval must occur. Measure the change in verbalized confidence distribution. **Retrieval claim**: blocking cache→conf attention collapses verbal confidence toward a template-conditional prior (near-uniform / population-mean); a matched-block at non-cache positions (§3.5.a) does not.

**M5 — Direction steering (signed dose-response).** Extract a **confidence direction** at the top M2 site via difference-of-means / LDA between high-verbal-confidence items and low-verbal-confidence items on a training split, then evaluate on a held-out split. Add α·direction at the cache position across α ∈ {−4, −2, −1, 0, +1, +2, +4}. **Directional claim**: verbalized confidence changes monotonically with α with the expected sign; answer accuracy stays roughly flat.

### 3.5 Controls and null hypotheses

For every intervention (M3, M4, M5), we run four matched controls (bundled as **M6**):

- **(a) Matched non-cache position control.** Same intervention, same layer(s), same magnitude, but at a matched *non-cache* position (e.g., mid-question, or a randomly chosen template token outside the post-answer window). Predicted: much smaller effect on verbalized confidence.
- **(b) Recall-strength null.** Split items by **recall strength** — e.g., proxied by TriviaQA popularity / answer-token log-prob percentile / model-generated frequency prior. If the M2 probe direction just tracks recall strength, its effect should collapse when restricted to items *matched on recall strength*. We report the probe R² and the M3/M5 effect *within recall-strength bins* to show the direction carries confidence signal *beyond* recall strength.
- **(c) Log-prob-restatement null.** Hold the sampled **answer token identity** and its log-prob **fixed** (by conditioning on a fixed prefix through `<EOA>`) and apply the M3 patch. Predicted: verbalized confidence still moves, falsifying the "verbalization is a fresh restatement of the answer log-prob" account.
- **(d) Answer-accuracy preservation.** For every intervention, report answer accuracy on the intervened prompts (measured *before* the confidence token, using the previously-committed answer). Predicted: accuracy roughly preserved — the interventions target the confidence pathway, not the answer pathway.

### 3.6 62-layer probe / intervention grid

Layer coverage that respects the 62-layer primary model:

```
probe_layer_grid = [5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55, 60]   # ~8%..97%
```

Percentile map: L5 ≈ 8%, L10 ≈ 16%, L15 ≈ 24%, L20 ≈ 32%, L25 ≈ 40%, L30 ≈ 48%, L35 ≈ 56%, L40 ≈ 65%, L45 ≈ 73%, L50 ≈ 81%, L55 ≈ 89%, L60 ≈ 97%. For M3/M4/M5 we take the top-K `(position, layer)` from M2's screen; the exact set is `method_sensitive` at Phase 1.5 of the experiment stage.

### 3.7 Post-answer window

Post-answer window = the positions of `<EOA>` and up to 4 following fixed template tokens (before `<conf>`). Confidence-generation position = the first `<conf>` token. Matched non-cache controls use positions inside the *question* body or the mid-question region — matched for token count and layer index.

## 4. Contribution

- **Dominant contribution**: A **causal-mediation account of verbalized confidence generation** in a modern 27B-parameter model — that the verbalized number is retrieved from a hidden-state cache written at answer-adjacent positions, not computed on-demand at the confidence-generation step. This is a mechanistic-interpretability finding about self-evaluation / metacognition in LLMs.
- **Supporting contribution**: A minimal, standard toolkit (linear probe + activation patching + attention-block + steering + a well-designed null battery) that other researchers can re-use for verbalization-time mechanisms (verbal explanations, verbal uncertainty, verbal introspection reports, …).
- **Explicitly rejected complexity**: (i) SAE / dictionary learning on the cache position (Unit Interpretation) — not needed; "confidence" already labels the direction. (ii) Formation Tracing across checkpoints — beyond inference-time claim. (iii) Downstream calibration edits or steering-for-calibration — that is Tuning & Editing, orthogonal to the diagnostic claim. (iv) Circuit-level head-by-head decomposition — the position × layer × attention-block resolution above is sufficient to land the claim; head-level refinement is a follow-up.

## 6. Risks & Mitigations

- **Risk R1 — Signal is a recall-strength artifact.** *Mitigation*: M6(b) recall-strength null within-bin analysis and probe residualization on log-prob percentiles.
- **Risk R2 — Effects driven by trivial token-fluency features (e.g., template tokens).** *Mitigation*: Matched non-cache control (M6(a)) at template tokens of similar identity/context; report intervention Δ per position, not aggregate.
- **Risk R3 — Answer-generation collapse under patching (patch destabilizes the answer, then confidence changes as a downstream artifact).** *Mitigation*: Answer-accuracy preservation check (M6(d)); when accuracy drops, exclude the item from the confidence-effect statistic.
- **Risk R4 — Probe overfits to seed-specific noise.** *Mitigation*: Train / evaluate on disjoint TriviaQA splits, report ≥3-seed variance, and use ridge regularization by default.
- **Risk R5 — Steering direction is site-specific and doesn't generalize.** *Mitigation*: Extract the direction on a training split and evaluate on held-out items; also validate on paraphrased templates in M6.
- **Risk R6 — 10-GPU-hour budget over-run.** *Mitigation*: M1 activation cache is written once and re-used across M2/M3/M4/M5. M3/M4/M5 use small per-run pools (≤200 clean/corrupted pairs at first), scaled up only if the initial signal is ambiguous.
