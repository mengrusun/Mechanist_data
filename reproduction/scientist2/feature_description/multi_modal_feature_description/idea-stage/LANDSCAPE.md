# Landscape: SemanticLens-style component → CLIP semantic-vector mapping for vision models

**Date**: 2026-07-13
**Scope**: Interpreted as — for every internal component *c* of a trained vision model (main: ResNet-50 on ImageNet), (i) select a small set of **reference inputs** that strongly drive *c*, (ii) embed those reference inputs with a **frozen multi-modal foundation model** (CLIP image tower), and (iii) pool to a single vector **v_c** placing *c* in the joint image–text semantic space. The reading is fixed by `task.md` (no ambiguity: the SemanticLens pipeline over ResNet-50/ImageNet with CLIP as the foundation embedder). Focus areas: neuron/channel labeling, reference-input selection, CLIP-based concept probing, evaluation protocols.
**Based on**: 100 papers retrieved from the mechanic-db cloud SEARCH service (interp_db, recent-mode, year_min=2019) plus arXiv-API cross-check on 5 targeted queries. See `RESEARCH_LIT.md` for the raw dump.

## 2. Core Landscape Narrative

**Where the field stands.** Automated concept-level labeling of vision-model components has evolved through three overlapping generations. The first is the **fixed-vocabulary / probe-dataset** era (Network Dissection, Compositional Explanations, INVERT): each internal unit is scored by how well its activations align with pre-labeled concept masks or discriminative controls; strong statistical rigor but bottlenecked by the vocabulary. The second is the **open-vocabulary caption / MLLM** era (MILAN, DnD, LLM-assisted Concept Discovery): a language model generates a natural-language description from an image set that drives the neuron; more expressive, but the description is a *string*, not a vector, so it does not compose with search / comparison / audit operations across many components. The third is the **frozen multi-modal encoder** era (CLIP-Dissect, FALCON, SpLiCE, Second-Order lens, and — as the culminating unified framework — **SemanticLens**): the reference inputs of each component are embedded with a frozen VL foundation model (usually CLIP), giving a single per-component *vector* in a joint image–text space, which turns interpretation into geometry (text search, cross-model neuron alignment, dataset shift monitoring, spurious-correlation detection).

**The specific pipeline in `task.md`.** The two claims — (i) top reference inputs summarize what a component encodes, and (ii) pooling their CLIP-image embeddings places the component in CLIP's semantic space — sit at the intersection of CLIP-Dissect (which uses CLIP's *similarity* to a concept probe set but not the pooled component vector), FALCON (which uses CLIP captions with a contrastive filter), and SemanticLens (which explicitly formalizes the component→CLIP vector, plus the four downstream operations: text search, comparison, labeling, audit). The "second-order lens" (Gandelsman) and "Interpreting ResNet-based CLIP" empirically corroborate the geometric premise: for CLIP-ResNet the effect of many neurons through attention pooling is approximable by a **single direction** in CLIP's image-text embedding space — direct evidence that a one-vector-per-component summary is well-posed inside CLIP itself, and by transfer plausible for other CNNs measured against CLIP.

**Recurring evaluation protocols.** (a) *Concept purity / description accuracy*: last-layer neurons of ImageNet-trained models where the class label is the ground-truth concept (CLIP-Dissect's headline benchmark); (b) *Human alignment*: crowdsourced judgements on which label a person finds most accurate for a hidden-layer neuron (MILAN, DnD user studies); (c) *Downstream utility*: use v_c for model auditing — spurious-correlation detection (SemanticLens, DORA, Reveal2Revise), cross-model neuron alignment (Rosetta Neurons, SPARC), dataset-shift monitoring (Bu & Gandelsman 2025); (d) *Statistical rigor*: INVERT and "Quantifying Structure in CLIP Embeddings" add hypothesis testing to counter the field's early over-reliance on cherry-picked qualitative examples.

**Consensus / disagreement.** Consensus: (1) The top-k activating input set is a reasonable, empirically useful summary of a mid/late-layer vision component. (2) Frozen CLIP is a competitive, cheap concept alphabet — no per-model training. (3) Many components are polysemantic; a single label is often incomplete. Disagreement: (a) Whether **activation matching in the probe set** (CLIP-Dissect) or **caption ranking with contrastive filtering** (FALCON) or **direct pooling in CLIP space** (SemanticLens) gives the most faithful summary. (b) Whether descriptions are **causally** faithful to how the neuron drives predictions ("From What to How" argues no — activation-based labels can miss the neuron's actual effect on outputs; second-order effect analyses shift the definition of what "labels" should track). (c) How the summary should handle polysemy — single vector vs. sparse decomposition (SpLiCE, SAEs, Concept Vectors, Discover-then-Name).

**Frontier (2024-2025).** The current frontier is (i) tightening the *geometry* of the mapping — statistical guarantees on discovered concepts (Quantifying-Structure 2025), sparse concept bases (SpLiCE, SPARC), attribution-based faithfulness (From-What-to-How 2025); (ii) scaling to broader model zoos (Rosetta Neurons, Prisma toolkit); (iii) driving **downstream audits** with the resulting vectors (Reveal2Revise, Ensuring Medical AI Safety, SemanticLens's melanoma / ABCDE case study). Vision-side sparse autoencoders and transcoders (Prisma) are converging with the CLIP-embedding line as competing / complementary component decompositions.

## 3. Sub-direction-Specific Work

- **Reference-input selection (which inputs drive component *c*)** — Network Dissection (per-pixel activation masks + concept masks); MILAN (top-activating image regions ranked by neuron activation); CLIP-Dissect (activation vector on a probing set); FALCON (top-activating *cropped* images + contrastive lows); DORA (Extreme-Activation set, data-agnostic). *Gap*: no principled comparison of "top-k full images" vs. "top-k crops" vs. "contrastive top vs. bottom" vs. "attribution-guided" reference sets for the same component with a common evaluation.
- **Pooling / mapping to a semantic vector** — SemanticLens (mean/pool of CLIP image embeddings of reference inputs); Interpreting Second-Order Effects in CLIP (single direction per neuron via attention path); Interpreting ResNet-based CLIP (single direction per neuron-head pair). *Gap*: the pooling operator is treated as a hyperparameter; no systematic ablation of mean vs. weighted (by activation) vs. attention-weighted vs. medoid vs. sparse-code, especially outside CLIP models.
- **Concept vocabulary / naming** — CLIP-Dissect (fixed vocab: 20k words), MILAN (open-vocab generation), DnD (MLLM), LLM-assisted Concept Discovery, Concept Visualization with WordNet, Discover-then-Name-CBM. *Gap*: naming is often confounded with quality of the underlying v_c; separating "was v_c faithful?" from "did we find a good name for it?" is under-studied.
- **Evaluation protocols** — Concept purity (Network Dissection IoU), CLIP-Dissect last-layer accuracy, INVERT discriminative test, MILAN & DnD user studies, "Quantifying Structure" statistical test. *Gap*: reproduction with **standardized** metrics for the same ResNet-50/ImageNet setup across CLIP-Dissect / MILAN / FALCON / SemanticLens is scattered across papers with slightly different vocab and probing sets.
- **Downstream audits** — SemanticLens (concept search, comparison, spurious correlation, ABCDE compliance); DORA (outlier concepts); Reveal2Revise & Ensuring Medical AI Safety (bias annotation + mitigation); Rosetta Neurons (cross-model concept alignment). *Gap*: audit fidelity as a function of the underlying v_c summary quality — how much do audits degrade when v_c is coarser vs. finer?

## 4. Structural Gaps

- **Gap G1 — "One-vector-per-component" faithfulness is well-tested inside CLIP-ResNet but not for arbitrary CNNs against CLIP.** *Competitive set*: SemanticLens, Interpreting ResNet-based CLIP (2025), Interpreting Second-Order Effects. *Why open*: the geometric result "each neuron ≈ single CLIP direction" was demonstrated for **CLIP's own ResNet backbone**; whether the same one-vector summary is faithful for an **ImageNet-supervised ResNet-50** measured through a frozen CLIP encoder is asserted by SemanticLens but the systematic per-component faithfulness (concept purity as a function of the pooled v_c) is not fully characterized.
- **Gap G2 — Sensitivity of v_c to reference-set size and selection strategy.** *Competitive set*: CLIP-Dissect, FALCON, MILAN, SemanticLens. *Why open*: reference-set size k, top-k vs. top-k-with-controls, cropping vs. whole image, and use of activation-weighted vs. uniform pooling are all treated as hyperparameters chosen by convention. A calibrated study of "how small can k be before v_c collapses" and "which pooling recovers concept identity best" is missing for ResNet-50 + CLIP.
- **Gap G3 — Layer/component granularity.** *Competitive set*: Network Dissection, CLIP-Dissect (5 layers of ResNet-50 in 4 min), SemanticLens, VCC. *Why open*: at what depth does v_c become semantically alignable to CLIP text; how do early conv channels (texture / edge) compare to late layer4 channels (object) in v_c stability and concept purity — this is asserted qualitatively but not systematically for the ImageNet + CLIP setting.
- **Gap G4 — Cross-model alignment via v_c.** *Competitive set*: Rosetta Neurons, SPARC, SemanticLens. *Why open*: v_c is proposed as a **shared coordinate system** across models; the natural verification (transfer of concept queries between ResNet-50, ViT-B/16, VGG-16, EfficientNet-B0 through v_c cosine geometry alone) is directly stated by SemanticLens but is the exact question the verify stage should stress-test — and there is no consolidated benchmark for it.
- **Gap G5 — Audit yield vs. summary fidelity.** *Competitive set*: SemanticLens, Reveal2Revise, Ensuring Medical AI Safety, DORA. *Why open*: the field has demonstrated the *existence* of audits enabled by v_c (spurious-feature detection, dataset shifts) but not the *dependency* on how v_c was constructed — is a text query "watermark" reliably retrievable regardless of pooling choice?
